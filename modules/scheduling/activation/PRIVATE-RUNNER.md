# Private-runner preflight (implementation only)

No runner, credentials, resource access, or live execution is authorized by this implementation. Existing Vercel entrypoints and their authorization rules are unchanged. This adapter is not an application route and starts no listener.

## External supervisor is mandatory

`supervise` is a library for a separately administered, trusted supervisor. There is deliberately no environment-driven launch command. The owner must provision and review that supervisor separately. Do not load policy, approval keys, executable adapters, runner identity, or attestations from caller-controlled environment variables or from the verifier. A process with only an approval JSON must not obtain credentials.

The supervisor receives fixed policy: an out-of-band pinned Ed25519 public key, the exact approved implementation revision, runner identity, immutable runtime image digest, source root, persistent private single-use ledger, and trusted host adapters for fresh remote source acquisition, runtime attestation, secret release, and worker execution. Bind `fetchSource` to `fetchRemoteSource` running outside the worker mount; never bind it to request JSON, a caller-supplied SHA or a locally generated manifest. Bind `execute` to `executePrivateWorker` with the verified source root and mandatory `WorkerContainment` host; do not accept a request-selected executable. Without containment the reference bridge returns BLOCKED and starts nothing. The supervisor implementation and policy live outside the verifier's writable/process security boundary. Use a separate OS identity and enforce filesystem/process isolation. Signature verification authenticates the exact UTF-8 payload bytes (not reserialized JSON); use Ed25519 with a detached base64 signature. No signing keys belong in this repository.

An approval has `version: 1`, `runnerId`, `runtimeDigest` (`sha256:` plus 64 hex digits), `sourceRevision` (full 40-hex Git SHA), `sourceManifest` (every tracked pathname mapped to its SHA-256), `resources` matching the hardcoded staging identities, ISO `expiresAt` at most one hour ahead, and a unique 20–100 character `executionId` containing only letters, digits, underscore or hyphen. Never include secrets in approval or manifest. The ID is atomically reserved before secret release and remains consumed after failure. The ledger must survive disposable runners, be owned by the supervisor UID, mode 0700, and never be rolled back, copied per runner, or pruned while approvals can be replayed. The trusted host must guarantee durable filesystem semantics and one shared atomic ledger across its runners; restoring a ledger snapshot invalidates the replay guarantee. Retrying requires fresh owner approval and ID.

## Source integrity and runtime

Before credential release, `fetchRemoteSource` acquires the fixed HTTPS repository's `refs/heads/staging/rrd-scheduling` into a fresh private bare repository, with global/system Git config, helpers, hooks, templates, file transport and prompting disabled. It fetches the branch, not a caller-selected commit; its fetched commit must equal the exact approved SHA. It derives the complete manifest from fetched Git blobs. Remote evidence must be at most 60 seconds old, with no future timestamp. The external supervisor compares remote manifest, signed manifest and every mounted source file, again before execution. Local branch labels are irrelevant; a detached mount is acceptable. Filesystem enumeration rejects ignored/untracked extra files and symlinks without executing checkout Git config or clean filters. `.git` alone is excluded from enumeration and must be inaccessible to the worker. This code was not fetched from or merged into permanent staging during remediation; genuine staging provenance remains UNVERIFIED until a future approved acquisition succeeds.

Mount source and Git metadata read-only before verification and throughout execution. Exclude `.git` and credential storage from worker access where the sandbox supports mount separation, without changing the verified source contents. A writable source mount defeats the time-of-check/time-of-use guarantee. Extra ignored files are now rejected even if Git would hide them. Git metadata, dependencies, the Node executable, the supervisor and TypeScript loader remain outside the source manifest: the separately attested immutable runtime digest must cover the entire executable closure. Install dependencies in a separately pinned read-only image path, not as extra files under the source mount; resolve the fixed loader only from that approved closure. The source root is a fixed trusted absolute path, not request input. Do not invoke dependency lifecycle scripts. Install the frozen lockfile in the approved image before any credentials are available. No dependency installation or artifact upload is permitted during credential-bearing execution.

The runtime attestation must come from trusted host enforcement, not booleans asserted by the worker. Require disposable non-root Linux, read-only source, private secret access, and restricted egress. Verify the actual host identity and image digest against approval. The process additionally refuses UID 0. Set host limits for memory/CPU/process count/core dumps and an independent wall-clock watchdog. The reference bridge requests external whole-containment termination at its 30-second deadline and waits at most five additional seconds for cleanup confirmation. It does not implement OS containment. The host must enforce an independent 60-second outer watchdog even when startup or the supervisor stalls. Require distinct supervisor/worker UIDs, private PID/mount namespaces, a non-delegated cgroup that the worker cannot escape, capability removal/no-new-privileges, syscall controls denying ptrace/setns/unshare/mount and access to host sockets, supervisor memory, keys, config and ledger. The mandatory `start` adapter launches with fixed IPC/stdio and no inherited environment; it must capture all output from launch, forbid new descendants during teardown, kill the whole cgroup and confirm it is empty and reaped. `child.kill()` or process-group signaling alone is not confirmation. The runtime attestation now explicitly requires distinct principals, no supervisor access, bounded resources and whole-tree termination. No host adapter, sandbox, watchdog or attestation service has been provisioned or certified here. Block ptrace, shared PID namespaces, untrusted volume writes and crash dumps. Do not permit concurrent untrusted workloads.

## Credentials and network

After signature, runtime, source and one-use checks, the external secret custodian returns only `DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `NEON_AUTH_BASE_URL`, `NEON_AUTH_COOKIE_SECRET`, and `ADMIN_DASHBOARD_KEY`. Do not retrieve production values or provider-management keys. No environment authorization, cloud credentials, `PG*`, `VERCEL_*`, `NODE_OPTIONS` or parent environment is forwarded. The worker receives credentials through private IPC, not arguments, environment, persisted files, logs or artifacts. JavaScript strings cannot be reliably zeroized: destroy the worker/container after use and disable memory dumps. Never print or hash secret material into logs.

Allow database TLS traffic only to the exact approved pooled and direct compute endpoints (including DNS resolution through a trusted resolver). Enforce the hostname-to-address policy at the host and account for endpoint address rotation; do not grant general outbound access. Deny inbound traffic, HTTP egress, Auth, email and billing endpoints. No live Auth requests occur.

The existing verified-TLS `inspectConnection` is reused unchanged: certificate rejection enabled, forced startup read-only defaults, `BEGIN READ ONLY`, identity-only SQL, statement/lock/connection/query timeouts, rollback on success and connection destruction in `finally` (destruction rolls back on failure). Both connections must return the exact approved project, branch, endpoint, database and `read_only=on`. Missing metadata fails closed; there is no hostname-only identity fallback. Before live approval, establish through trusted Neon/control-plane evidence that these server settings are authoritative and cannot be user-spoofed. Least-privilege existing staging roles are preferred; role/privilege changes require their own approval.

Auth checks verify URL configuration binding and minimum secret lengths only—not sign-in, membership, sessions, entropy, or production-secret separation. A PASS must not be interpreted otherwise.

## Reporting and cleanup

Worker output is IPC-only. A report is provisional until exactly one schema-valid report, zero forbidden stdout/stderr throughout execution, observed exit code 0 with no signal, the subsequent `close` event confirming closed streams, and successful external whole-tree cleanup. Duplicate/malformed/trailing output, missing exit or close, timeout, nonzero/signal exit, and false/rejected/stalled cleanup all yield BLOCKED; PASS is never returned on first IPC. Errors and child output are discarded, not logged. BLOCKED can return with cleanup unconfirmed after a bounded wait; that never certifies termination and requires the independent host watchdog and operator quarantine. The external supervisor may publish only `{ "status": "PASS", "reason": "OK" }` or BLOCKED with one fixed reason: `AUTHORIZATION_BLOCKED`, `CONFIGURATION_BLOCKED`, `IDENTITY_BLOCKED`, `CONNECTION_BLOCKED`, `EXECUTION_BLOCKED`. Never publish raw exceptions, approvals, credential values, or captured child output. The supervisor library returns a sanitized report; the host must also sanitize its own bootstrap/uncaught errors.

Close pools, kill all remaining processes, destroy disposable storage and secret references, and retain only sanitized reports and non-secret provenance evidence in private storage. Preserve the anti-replay ledger. No writes/migrations are performed; no database rollback operation is needed beyond transaction teardown. Neon compute wake-up, audit records, and private-runner charges remain possible. Rotate credentials if exposure is suspected, under separate authority.

The supervisor, host administrator, runtime image, secret custodian, network policy and authoritative resource identity remain trust boundaries. A compromised privileged host can read credentials or falsify results. The exported verifier function is deliberately not its own access-control boundary: possessing credentials permits bypassing it. Enforce secret custody and execution restrictions externally.
