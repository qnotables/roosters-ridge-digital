## Non-executable policy and external requirements

`runner-policy.json` is deliberately **not** the `Approval` schema: it has no live signature, execution ID, expiration or trusted key, and `authorizationAllowed` is false. UNVERIFIED markers must not be replaced by invented evidence. The manifest contains the original authorization code/docs; this separate policy's own checksum is recorded in `artifact-checksums.json` rather than recursively including itself in the approved source.

Before any future execution, owner-administered infrastructure must independently establish: separate supervisor/worker identities and inaccessible custody boundaries; immutable complete runtime and source; authentic host attestation tied to the approved image/runner; trusted clock; persistent private shared anti-replay storage; deny-by-default networking with controlled DNS and enforced hostname/SNI binding (shared Neon IP alone is insufficient); least-privilege exact staging credentials; no downloads/installs; no public listener; dump/ptrace restrictions; outer 60-second proposed deadline plus 30-second child cap; kill and confirm the entire process tree; bound CPU/memory/processes/IPC; sanitize all host errors; destroy secret-bearing processes/storage while retaining the ledger. No such infrastructure has been provisioned or certified.
